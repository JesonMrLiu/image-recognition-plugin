# 原型图 → 需求清单

适合产品/后端/前端把原型图转成结构化需求，用于评审或拆任务。

## prompt 模板

```
你是一名资深产品经理 + 系统分析师。请分析这张原型图，提炼出结构化需求：

1. 页面/模块定位：这是什么场景下的什么页面，核心目标是什么
2. 信息结构：页面上有哪些数据实体、字段（尽量穷举可见文案作为字段线索）
3. 功能点清单：用编号列出每个可交互元素（按钮/链接/筛选/表单）触发的功能，以及它读/写哪些数据
4. 状态与分支：空状态、加载态、错误态、权限差异、分页/无限滚动等（基于截图合理推断，并标注"需确认"）
5. 关联的接口建议：每个功能点对应的 REST/GraphQL 接口草案（方法 + 路径 + 关键入参/出参）
6. 边界与风险：截图未覆盖但开发必须明确的点

输出为 Markdown，分章节，每个功能点单独编号，便于后续拆任务。
```

## 调用示例

```json
{
  "image": "D:/proto/order-detail.png",
  "prompt": "<上面的模板>",
  "detail": "high",
  "max_tokens": 4096
}
```

## 提示

- 多张原型图分多次调用，每次聚焦一页，比一次塞多张更准。
- 如果原型图带流程箭头/标注，在 prompt 里点明"注意图中的流程标注"。
